# 中文操作工作区

打开部署生成的本地启动地址，进入 **任务**。启动地址只属于当前进程；普通刷新会保留会话，服务重启后请用新的启动地址。界面不会预置任务，也不会自动启动测试。

## 先配置模型

打开 **模型设置**，新增配置。选择 DeepSeek、GLM 智谱、LongCat 或自定义兼容服务，填写配置名称、服务地址、模型名称与密钥，然后保存。页面会显示实际请求地址，便于发现重复填写 `/chat/completions`。高级设置可以调整单次调用时限和最大输出 Token 数。

保存不调用服务；**测试已保存连接** 才会发送最小连接测试。成功和失败都会显示实际结果，失败不会切换到另一家服务。重新打开配置时密码框为空，页面只显示“已保存密钥”。更换服务商或地址时需重新填写密钥。删除后列表会显示实际删除结果。

这里支持通用兼容 Chat Completions 的接口，不承诺每家厂商的所有扩展功能。所选服务会接收任务上下文与有限证据摘录。预设地址和模型示例可编辑，实际可用性取决于您的服务账户。预设文档：[DeepSeek](https://api-docs.deepseek.com/)、[GLM](https://docs.bigmodel.cn/)、[LongCat](https://longcat.chat/platform/docs/en/)。未进行真实供应商验证。

## 新建任务，先规划再批准

1. 在 **任务** 点击 **新建任务**，填写名称与测试目标。背景及初始指导在“补充信息”中。
2. 按行粘贴网址、域名或 IP，或上传 UTF-8 CSV，点击 **预览并检查资产**。表头为 `target,name,group,notes`。未提供协议时采用 HTTPS；预览会列出规范化的完整目标、重复行和错误行。所有错误必须修正，编辑输入后需重新预览。重复只保留首次记录。
3. 选择 **基础观察（不调用模型）**，或选择配置模型参与规划和分析。高级角色设置可分别选择 Commander（规划）、Scout（观察分析）、Soldier（测试分析）和 General（复测建议）。角色是实际逻辑执行角色，不代表独立的后台进程。界面显示真实角色模型选择；基础观察模式会清空所有模型选择。
4. 核对排除范围、允许的 GET/HEAD、请求次数、预留字节、执行时间和模型调用额度。高级边界显示授权有效期、单次请求时限和响应上限。保存的精确数值不会被自动放大。
5. **保存草稿**，或 **保存并规划新一轮**。规划可能调用配置的 Commander，但不会访问目标。
6. 在轮次 **概览** 核对冻结范围与每条精确动作，勾选动作、填写批准署名，再点击 **批准选中并开始**。**仅批准选中** 不会启动；随后可单独开始已批准动作。未批准动作不会执行。

支持有界 GET / HEAD 观察、模型分析和人工复核，不支持通用命令或任意工具。来源按协议、主机、端口整体登记；已登记来源下的新路径仍需精确动作批准，其他子域名、主机和端口不会自动加入。HEAD 观察不是完整安全响应头审计。

## 测试过程与人工指导

轮次顶部显示实际阶段、停止原因和下一步。**暂停** 或 **结束本轮** 在有界操作结束后生效，界面会先显示等待状态。暂停后需明确继续；结束后不能继续。额度不因暂停、结束或失败退回。

在 **测试过程** 填写指导，点击 **发送并重新规划**。消息首先持久排队，**已排队不等于已消费**；消费后会显示实际消费者标识与结果。模型据此提出新动作，但仍需您回到概览批准。暂停或结束可以使尚未发送的指导失败；失败的指导需重新发送。

消息类型还可选择 **优先处理动作**（填写待执行动作标识）或 **请求漏洞复测**（填写漏洞标识）。漏洞详情也有直接复测按钮。模型失败时修正被引用的配置，然后明确继续。已完成请求不会重放；不确定的重启结果需要检查。

编辑草稿只影响新轮次。顶部区分本轮冻结草稿版本与最新草稿版本；**规划新一轮** 保留旧记录，并创建独立预算。轮次选择不会因轮询跳转；历史可加载更多。

## 覆盖与漏洞复核

**资产与覆盖** 同时显示当前有效覆盖的分子/分母、人工检查、未开始/失效/不适用状态和历史执行回执。筛选不改变全局分母。点击状态查看证据、失效原因与人工评估。人工完成需有效且目标匹配的事实；不适用需署名与理由，并单独排除分母。预留字节和时间属于额度消费，不是实测流量；风险、成本值不是货币。

在 **漏洞** 打开完整案例，可查看目标、描述、影响、复现、修复建议、真实回执、内容哈希、来源、叙述及复核历史。内容摘录最多 4096 字符，可能不完整，已隐藏常见敏感字段，但不保证删除任意敏感文字；它不是完整 HTTP 流量。

模型提出候选，不自动确认。您可以从有效真实事实创建候选、编辑完整叙述、请求复测并批准新增动作。人工复核须使用同目标的较晚独立回执，并填写与原报告者及事实创建者不同的署名；同一证据不能复核自身。署名用于本地归因，不验证第二位人员身份。General 的模型建议仍是未采纳建议，最终状态由人工复核保存。

支撑事实被主动撤销、授权过期或依赖失效时，发现显示 **证据已失效**，保留原始叙述与历史复核。**失效不等于已修复或漏洞不存在**。如叙述保存不完整，详情会显示可修复状态。

## 报告

打开 **报告** 查看本轮预览，或下载 HTML、Markdown、JSON。预览使用同源认证和禁止脚本、表单、弹窗的隔离框架。导出保留当前有效性、缺口、完整叙述、历史复核和证据来源。内容中的标签按文字显示。当前批次完成不代表委托验收完成，观察覆盖也不证明没有漏洞。

本 UI 功能版本使用既有报告渲染器；独立报告的排版精简与打印样式是后续视觉检查项，完成后才进入最终部署门槛。真实浏览器验收使用 [合成回环 fixture](OPERATOR-BROWSER-TESTS.md)，不能当作真实目标或 DeepSeek/GLM/LongCat 可用性验证。

维护者可通过 `tests/browser/operator-workspace-journey.ps1` 的固定 Stage 运行实际浏览器片段（需要 npx，固定 `@playwright/cli@0.1.23`）。先按 fixture 文档建立新的专用空状态，再 Bootstrap、Models、Task；GuidanceQueued / Pause / Cancel / ActiveRestartPrepare 需要配合 fixture 的 Arm / Release / Restart，不能把排队或取消解释为模型已消费。Approve 只批准而不启动；General 复测同样需另行批准。其余固定 Stage 对应完整漏洞、覆盖、导出、角色覆盖、模型修正与状态读取检查。片段必须按验收步骤使用，不会清空或重置已有状态。所有 CLI 原始日志与截图保存在忽略的 `.superpowers/operator/ui-validation/`，启动片段不输出到普通日志；不得把这些私密过程日志作为用户输出发布。补充本地组件回归：`node tests/browser/operator-workspace-unit.mjs`。完整验收过程与实际计数记录见本次本地验证报告。
