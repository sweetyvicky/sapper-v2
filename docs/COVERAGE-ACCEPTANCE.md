# 覆盖工作台验收记录

本轮在 `feature/coverage-console` 独立实现日常项目的资产覆盖、测试覆盖、执行过程和证据下钻。基础为 `feature/authorized-pentest` 的 `d471de5`；不修改 `master`。参考来源和独立实现取舍见 [ARTEX 研究记录](ARTEX-REFERENCE.md)，操作入口见 [工作台说明](COVERAGE-CONSOLE.md)。

## 已实现与验收口径

- 版本化资产和检查计划，分开计算资产覆盖与应测单元覆盖；零分母为空，不适用须有归属与理由，修订保留历史。
- 计分依据为目标、方法、任务、回执与有效事实的完整关联；普通 HTTP 成功不会完成人工安全检查，撤销和过期会移除完成计分。
- Commander、Scout、Soldier、General、Watchdog、事实图及既有批准/预算/期限控制保留。新增界面只读，不提供批准或执行接口。
- 中文覆盖矩阵、声明资产关系、任务与审计过程、证据/发现详情；筛选不改变全局分母；详情采用可读摘要，可展开原始元数据。
- 实时只读查看、单文件离线快照、九阶段实际隔离过程回放。演示中的人工判定明确标注为演示记录，不能当作真实漏洞结论。

本次修复后的覆盖/运行/工作台专项与既有边界/证据回归，在固定 Python3.12、3.13 容器中串行各通过134项，均将 ResourceWarning 作为错误，并覆盖直接和传递依赖争用。该数字是修复覆盖范围的验证，不代替最终源码的完整套件与PR CI；父任务在最终复审后绑定完整验证的准确版本。

## 部署与交接边界

Windows实时显示进程使用专用普通Docker bridge、只读源码和状态挂载、主机127.0.0.1端口。该显示容器具有网络能力，不能称为操作系统级断网环境；代码没有目标访问或执行入口。执行测试和演示生成保持断网。Docker29.8的internal-only网络不发布主机端口，设计调整有实测和[维护者解释](https://github.com/moby/moby/discussions/53256)。

当前仍是受控Mock建议与有界HTTP观察基础，没有新增真实模型代理或自主漏洞检测器。多SQLite读取逐库一致，不承诺跨库原子快照。身份字段为归属记录，非多人认证。离线帧的有效性代表采样时刻，不会重新访问已删除的临时靶场。

后续开发应继续保持版本化计划、严格来源链、失效撤回、显式分母与只读查看边界。增加资产导入、检查模板、多人审批或真实模型适配器时，单独设计输入、执行权限和失败行为，并附行为测试、独立审查与固定源码验收记录。

## 可重复的浏览器回归

`scripts/coverage-console.ps1` 是查看入口；浏览器验收脚本位于 `tests/browser/coverage-console.js`，不属于生产运行依赖。它针对 `dashboard-demo` 导出的真实九帧数据，验证 DOM 中每帧指标/状态、筛选分母、四个页面、详情与焦点、回放以及零额外资源请求。使用固定的测试工具版本，在浏览器已经打开所生成的演示页面后运行：

```powershell
npx --yes --package @playwright/cli@0.1.23 playwright-cli -s=coverage-check run-code --filename=tests/browser/coverage-console.js
```

会话名应与打开该演示的测试会话一致。本轮工具限制 `file:` 导航，因此使用本机固定文件预览，不能据此声称自动化验证了直接文件协议。原始浏览器控制器采用固定路径，不能把生产状态目录暴露为通用文件服务器。

两项界面边界经独立复核和实际浏览器确认：全部6项不适用时，显示空比例及6项排除数；关闭自动刷新后，可见事件不增加读取，手动刷新仍产生一次读取，重新开启自动刷新可恢复。
